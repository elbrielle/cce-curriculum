# CCE Curriculum Agent Instructions

Read `CLAUDE.md` and `PLANNING.md` before substantive curriculum work.

For Canvas lesson production, read and follow `cce-curriculum/notes/canvas-lesson-production-workflow.md`. The approved reference implementation is the Week 0 Day 2 teacher/student pair under `build/canvas/`.

For writing or auditing any Facilitator Guide, Student Guide, deck, or notebook page, load and follow the `cce-module-authoring` skill (`build/codex-skills/cce-module-authoring/SKILL.md`). Print its self-audit table before handing off.

Non-negotiables:

- Canvas is the sole active production, review, and delivery environment for teachers and students.
- GitHub preserves source and backup and hosts the generated public planning mirror. It is not a classroom-delivery environment. The MkDocs site remains a legacy archive; use `public-site/` for the approved mirror and do not revive or deploy MkDocs unless the user explicitly requests archival work.
- Every lesson receives a coordinated Teacher Facilitator Guide and Student Guide.
- Licensed workbook, Climber Notes, H&L, and Xello binaries or screenshots stay out of Git and the public site. Upload them only to authenticated Canvas.
- Never store a Canvas token in the repository, a script, a command-line argument, or an output log.
- The Canvas course is a Commons master. Agents never publish modules, pages, assignments, quizzes, discussions, or orientation content by default, including after QA passes. Only Elisha or another teacher publishes selected content for that teacher's students. Preserve any owner-published state unless Elisha explicitly asks for a publication-state change; do not treat unpublished curriculum as incomplete.
- Module publication is the student release gate. Canvas files referenced by course pages or module content, including images, linked PDFs, decks, and annotation files, and every ancestor folder must remain unlocked, unhidden, and free of availability dates. Never use file/folder locks as a substitute for leaving a module unpublished. After any Canvas builder, run `build/canvas/run_builder_with_resource_access.py` or the coursewide resource-access finalizer and require zero restricted referenced resources without changing publication states.
- Preserve the approved plain-language, visual, accessible Week 0 Day 2 quality bar. Do not mass-copy raw Markdown into Canvas.
- Zero cognitive overload for 8th graders: Keep student-facing language lean, active, and uncluttered. Strip all developer jargon (e.g., "licensed page images") and state administrative codes from student guides.
- Thorough Teacher Facilitator Guides: Provide minute-by-minute 50-minute pacing benchmarks (with 10-min cushion), look-fors, common misconceptions, and answer keys. The 50-minute flow must be explanatory, offering concrete examples of the discussion/task (e.g. give examples of what to ask), not just curt outlines.
- Anti-redundancy & surface integrity: Do not force students to duplicate/copy-paste work between platforms, workbooks, and journals. Respect the single Response Home. Student directions must explicitly state *where* to write their response (e.g., "In your CCE OneNote").
- Slide deck excellence (The "Stanley Standard"): Decks must include Do Now bellringers, explicit book/app click paths, concrete partner roles, visual countdown timers, authentic app screenshots (including Launchpad/Xello icons for ESL support), and "You Are Done When" completion checklists. Slide text must NEVER contain teacher planning or instructional language (e.g. "not another worksheet", "stop twice during the tour").
- Automated multi-platform parity: Maintain continuous lockstep across Canvas (course 98060), Google Drive (`iisd-drive:VILS27/Units_CCR`), and the GitHub public site. The similarly named `iisd-drive:27 CCR Planning` folder is a legacy archive and is never a production or parity destination.
- Google Drive routing: use the Drive connector as the primary discovery, stable-ID, sharing, and verification path, and the Google Slides connector for native deck edits and render QA. Within `VILS27/Units_CCR`, route native files that teachers open with Make a copy into the matching unit's `Google Masters/` folder; route downloadable PDF, PPTX, DOCX, and XLSX releases into `Download Releases/`. Rclone may inventory or copy ordinary stored binaries under the canonical Units_CCR hierarchy; never use `rclone sync` without explicit approval, never use the legacy `27 CCR Planning` folder for parity, and never claim that a raw PPTX transfer updated a native Google Slides deck.
- OneNote Integration: Stagnant PDFs and awkward 1x1 tables for worksheets should be avoided. Prioritize generating native, resizable OneNote pages.

- ESL / Emergent Bilingual Scaffolds: Use strategic, proficiency-responsive supports rather than automatic line-by-line translation. Maintain the same grade-level thinking target while adding a focused word bank, visual or modeled example, oral rehearsal opportunity, and optional sentence stem where language could hide what a student knows. Translate or pair home-language equivalents for essential directions, safety language, and high-value vocabulary when it materially improves access; do not assume every EB student speaks Spanish, and do not duplicate every English sentence in Spanish by default. Supports should help students produce increasingly independent academic English and should be removable or expandable by the teacher.

- OneNote Automation & Naming: Combine daily work and Exit Tickets into a single page inside the "CCE Work" tab to reduce clicks. Use extremely clear, recognizable titles (e.g., "Day 2: Career Research & Exit Ticket") so teachers can easily distribute them. Build worksheets using HTML tables with absolute pixel widths (`width="850"`) and embed ESL sentence stems natively.

- Teacher-selectable response routes: OneNote is an owner-specific native derivative, not a replacement for the shared curriculum artifact. Preserve an equivalent printable PDF or paper route and, when the lesson already uses one, the private Canvas response. Before class, the teacher selects one response home for that class. Students complete the work in that one place only; never require copying between OneNote, paper, Canvas, FYF, H&L, or Xello. A OneNote deployment must not delete, hide, or deprecate the shared PDF/Canvas route.

- Teacher Facilitator Guides (The "Avil Standard"): 50-minute flows must not be curt or shorthand. Write in a natural, expansive, supportive voice. Use conversational, actionable steps (e.g. "Welcome students to class"). Quote the exact questions teachers should ask. List explicit step-by-step activity instructions rather than summarizing. Provide clear media & vocab cues. When editing `build_wk1.py` or similar scripts, use HTML `<ul>` and `<li>` tags inside the Python string to render these bulleted instructions perfectly on Canvas.
